# 사내 자산관리 시스템 기능 개선

자산 등록부터 출고, 재고실사, 파기 결재까지 자산의 전 생애를 다루는 사내 업무 앱에, 검수 피드백 14장·40건을 받아 원인을 찾고 설계를 정하고 게시본으로 검증해 반영한 작업이다.

> 회사 업무로 만든 앱이라 수식·컨트롤 정의·흐름·데이터는 올리지 않고, **어떤 일을 했고 무엇을 판단했는지만** 적었다.

| 개요 | |
|---|---|
| 기간 · 역할 | 2025.11 ~ 담당 · 검수 피드백 반영 2026.09 · 단독 담당 개발자(기능 설계·구현, Dataverse 스키마·보안 역할 변경, 흐름, 게시 검증) |
| 범위 | 기존 앱(화면 골격)에 기능 추가·개선. 공용 헤더 컴포넌트는 다른 팀 담당이라 제외 |
| 기술 | Power Apps 캔버스(Power Fx) · Dataverse · Power Automate · SharePoint · Teams 승인 · `pac` CLI |

---

## 앱이 하는 일

자산 등록·조회·수정, 바코드 라벨 출력, 출고·부서 간 이관, 부서 재고실사, 파기 신청·승인(전자결재 연동), 조직 기준 통계, 총무 담당의 실사 결과 처리까지 화면 11개로 구성된 앱이다.

## 일하는 방식

- **피드백부터 판정했다**: 40건을 게시본 소스와 대조해 이미 있음 13 · 일부 있음 7 · 없음 18 · 앱 밖 문제 2로 나눴다. "구현 안 됨" 지적 가운데 실제로는 데이터 문제였던 것(부서명 불일치로 0건 표시)을 따로 짚고, 공수를 21인일로 산정했다.
- **검증은 게시본으로 했다**: 게시된 앱 소스를 내려받아 비교해 "저장했다"가 아니라 "게시됐다"를 확인했다.
- **되돌릴 길을 먼저 만들었다**: 데이터를 지우고 다시 넣는 작업은 넣는 쪽부터 성공시키고, 원래 값은 파일로 백업했다.
- **요구 범위만 고쳤다**: 작업 중 보인 다른 개선점은 따로 적어 두고 손대지 않았다.

## 대표 문제와 해결

### 1. 라벨 프린터 출력 — 앱 안에서 바코드를 직접 그려 PDF로

- 문제: 화면을 통째로 인쇄하던 구조라 라벨이 많으면 잘리고, 라벨 한 칸이 한 장인 롤 라벨 프린터에 맞지 않았다.
- 해결: Power Fx 안에서 Code128 바코드 인코더를 직접 구현해 라벨 HTML을 만들고, 흐름이 SharePoint에 저장하면 앱이 PDF로 여는 구조를 만들었다. 흐름 안에서 PDF로 바꾸는 방법은 리다이렉트 문제로 실패해 버렸다.
- 검증: 같은 로직을 별도로 만들어 공개 바코드 라이브러리와 비트 단위로 대조했다. 라벨마다 1페이지 벡터 PDF가 나오는 것을 확인했다.

### 2. CSV 일괄 업로드 — 파일을 읽지 못하는 캔버스 앱에서

- 문제: 캔버스 앱은 첨부 파일 내용을 읽지 못하고, Dataverse 양식에는 첨부 컨트롤도 나오지 않는다.
- 해결: 첨부 컨트롤은 SharePoint 양식에서 빌려 오고, 흐름은 파일을 텍스트로만 바꿔 준다. 파싱과 검증은 앱에서 헤더 이름 기준으로 하고, 유효한 행만 저장하고, 실패는 행별 사유로 돌려준다.
- 결과: 신규 등록형(자산등록)과 기존 갱신형(재고실사) 두 가지를 만든 뒤 재사용 가능한 형태로 정리했다.

### 3. 조직 권한 범위 — "부서장은 자기 팀만"

- 문제: 부서 필터가 자유 텍스트라 권한 개념이 없어, 부서장이 다른 부서를, 팀원이 전사를 볼 수 있었다.
- 해결: 로그인 사용자의 Dataverse 조직(사업부) 위치를 권한으로 삼아, 최상위면 전사, 부서면 자기 부서와 하위 팀, 팀이면 자기 팀만 고를 수 있게 했다. 통계·총무·파기 신청 세 화면이 같은 규칙을 쓴다.
- 함정: "부서를 눌러도 자산이 안 나온다"는 제보를 추적했다. 16건 중 12건이 조직도에 없는 부서명이라 데이터부터 맞췄다.

### 4. 전자결재 연동 — 결재는 앱이 아니라 흐름이 처리

- 파기 승인을 사내 전자결재에 태웠다. 앱은 기안·결재선을 만들고 흐름을 부른다. Teams 승인 카드 발송과 결과 기록은 흐름이 맡고, 결과를 파기 신청과 자산 상태에 되돌리는 것은 앱이 맡도록 나눴다.
- 실제 데이터로 상신 → 흐름 → Teams 승인 → 앱 반영까지 끝까지 검증했다.

### 5. 전체 재검증에서 잡은 결함 — 영구 자산이 결재 없이 파기될 수 있었다

- 14장을 모두 반영한 뒤 게시본 소스를 요구와 1:1로 다시 대조했다.
- 화면을 열 때는 새 규칙(4월 시작 회계연도, 영구 자산 99년)으로 계산하는데, 처리 버튼 2개는 옛 계산식을 쓰고 있었다. 그래서 영구 자산이 "만료"로 보여 전자결재 없이 파기 완료될 수 있었다.
- 버튼 쪽 계산을 맞추고, 게시 후 바뀐 곳이 그 부분뿐인지 비교로 확인했다. 같은 계산이 여러 곳에 있다는 점은 주의 사항으로 남겼다.

## 그 밖에 반영한 것

- 자산 목록 페이지 번호·열 정렬·반응형 열 폭, 등록 화면 필수 입력과 담당자 지정
- 잔존가 계산을 4월 시작 회계연도 기준으로 전 화면 통일
- 출고 화면의 인수부서 선택과 처리 필수 조건, "출고" 상태 추가
- 부서 재고실사 판정 규칙 정리(파일에 있으면 보유, 없으면 미보유), 총무 화면의 조직 체크 패널과 처리 방안
- 화면 세 곳의 Excel(CSV) 내보내기와 완료 팝업
- 자산 등록 시 권한 오류를 앱이 아닌 Dataverse 보안 역할 문제로 진단해 역할을 수정
- 같은 환경의 전자결재 앱 개선(폰 대응, 결재라인 표시, 기간 검색, 기안일자 자동 기록, 승인 카드 중복·날짜·링크 문제, 평일 기준 연차 계산, 통합 테스트)
