# 캔버스 앱 CSV 내보내기 팝업 키트

DemoAssetManagement에서 **세 화면**에 붙인 "엑셀 내보내기 → 완료 팝업 → 파일 열기" 패턴을
떼어낸 것이다. 네 번째부터는 이 폴더에서 꺼내 쓴다.

| 화면 | 버튼 | 파일명 | 폴더 |
|---|---|---|---|
| `scrStockTakeAdmin` | `btnSaExcelExport` | `재고실사_yyyymmdd_hhmmss.csv` | `재고실사` |
| `scrDisposalRequest` | `btnDrExcelExport` | `파기신청_…` | `자산파기` |
| `scrDisposalApprove` | `btnDaExcelExport` | `파기승인_…` | `자산파기` |

셋 다 2026-09-14에 게시본 종단 검증 완료. 이 폴더의 수식은 게시본에서 `pac`으로 받아 옮긴 원문이다.
팝업 모양(버튼 행 그림자·높이, 제목 굵기, 폰 폭 대응)은 2026-09-30 게시본 기준으로 갱신했다.

## 파일

| 파일 | 용도 |
|---|---|
| `01-button-onselect.txt` | 내보내기 버튼 `OnSelect`. 골격 + 실제 구현 3종 |
| `02-dialog.yaml` | 완료 팝업 한 벌(컨테이너·라벨 3·버튼 행). 화면 직속에 붙여넣는다 |

`02`의 `{{PFX}}`는 화면마다 다른 2글자 접두어다. 붙여넣기 **전에** 치환한다.

```bash
# 예: 자산출고 화면이면 Ao
sed -e 's/{{PFX}}/Ao/g' 02-dialog.yaml > /tmp/dlg.yaml
```

`AppTheme.*`는 앱이 쓰는 테마 컴포넌트 참조다. 자기 앱 이름으로 바꾸거나 `RGBA(...)` 리터럴로 바꾼다.
`{TENANT}` / `{SITE_NAME}`은 SharePoint 호스트와 사이트명이다. **두 곳 다 치환해야 링크가 열린다.**

---

## 전역변수 3개는 화면끼리 공유한다

| 변수 | 내용 |
|---|---|
| `gblExportFolder` | 폴더명. **슬래시 없이** (`재고실사`) |
| `gblExportFileName` | 파일명 (`재고실사_20260914_150200.csv`) |
| `gblExportDone` | 팝업 표시 여부 |

**접두어를 붙이지 않는다.** 화면마다 팝업 인스턴스는 따로 두지만 변수는 같은 것을 쓴다.
한 번에 한 화면만 보이므로 충돌하지 않는다.

---

## 전제 — 이것부터 확인

1. **플로우 `자산관리-목록CSV내보내기`가 앱에 추가돼 있어야 한다.**
   인자는 3개: `Run(fileName, rowsJson, folderName)`.
   Studio의 흐름 추가 목록에 안 보이면 솔루션에 없는 것이다
   (Power Apps 솔루션 → Common Data Services Default Solution → 기존 항목 추가 →
   클라우드 흐름 → **Dataverse 외부** 탭).

2. **대상 폴더가 SharePoint에 미리 있어야 한다.**
   SharePoint 파일 만들기는 없는 폴더를 자동 생성하지 **않는다.**
   자산관리 라이브러리(내부명 `DocLib`, 사이트 `/sites/{SITE_NAME}`) 아래에
   자산파기 / 재고실사 / 자산목록 / 자산출고 / 리포트 5개가 만들어져 있다.
   새 카테고리를 쓰려면 폴더부터 만든다.

## 붙이는 순서

1. 트리에서 **화면**을 선택 → `02-dialog.yaml` 붙여넣기 (Ctrl+V)
2. 제목줄 버튼 컨테이너에 `ModernButton`을 하나 만들고 (`Text = "엑셀 내보내기"`, `Width 120`, `Height 40`)
   **속성 드롭다운이 `OnSelect`인지 눈으로 확인한 뒤** `01-button-onselect.txt`의 골격을 채워 붙여넣는다
3. 앱 검사기 오류 0 확인 → 저장 → 미리보기에서 실제로 한 번 내보내 SharePoint에 파일이 생기는지 확인 → 게시

## 함정 (전부 실제로 당한 것)

### 1. `파일 열기`에는 `?web=1`이 반드시 있어야 한다

없으면 브라우저가 CSV를 **다운로드**해 버린다. 붙이면 Excel Online으로 열린다.

| URL | 결과 |
|---|---|
| `….csv` | 새 탭이 되돌아감 = 파일이 다운로드됨 |
| `….csv?web=1` | `_layouts/15/Doc.aspx?sourcedoc={…}&action=default` 로 리디렉션 = Excel Online |

게시본에서 실제 파일 URL로 확인했다.

### 2. `folderName` 인자에만 슬래시를 붙인다

```
Set(gblExportFolder, "재고실사")      // 슬래시 없음 — 표시·URL 조합용
.Run(…, …, "/재고실사")               // 슬래시 있음 — 플로우 인자
```

플로우의 파일 만들기 경로가 `"/DocLib@{triggerBody()?['text_2']}"`라
앱이 넘긴 값이 `/DocLib` 뒤에 그대로 붙는다.

새 디자이너에서 폴더 경로 필드에 슬래시를 타이핑하면 **동적 콘텐츠 메뉴를 여는 트리거 문자로
소비되어 사라진다.** `concat('/DocLib/', ...)` fx 삽입도 네 번 시도해 모두 반영되지 않았다.
그래서 앱 쪽 인자에 슬래시를 포함시키는 방식으로 우회했다. **플로우는 고치지 않는다.**

### 3. 버튼 행 `Height`는 반드시 32로 준다 — 기본값 200이 넘친다

오토레이아웃 `GroupContainer`의 기본 `Height`는 **200**이다. 버튼 행에 높이를 안 주면
팝업 안쪽 공간(228 − 패딩 48 = 180)을 넘치는데, 팝업이 넘친 부분을 잘라내서 겉보기엔
버튼 아래가 조금 비어 보일 뿐 원인이 드러나지 않는다. 버튼 행은 `Height 32`(버튼 높이)·
위아래 패딩 없음으로 둔다.

```
PaddingTop(24) + 제목 32 + 12 + 파일명 32 + 12 + 경로 32 + 12 + 버튼 행 32 + PaddingBottom(24)
= 212  ≤  228
```

같은 이유로 **기본 `DropShadow.Light`도 끈다**(`DropShadow.None`). 켜 두면 버튼 3개가
팝업 안에서 따로 상자에 갇힌 것처럼 보인다. 테두리처럼 보이던 선이 사실은 이 그림자였다.

제목은 `FontWeight.Semibold`로 위계를 준다. `Size`를 18로 키우면 기본 높이 32 안에
안 들어가 **라벨 자체에 세로 스크롤바가 생긴다** — 16을 유지한다.

폭·높이·X는 폰에서 안 넘치게 쓴다(`Width = Min(480, Parent.Width - 32)`,
`X = Max(16, (Parent.Width - 480) / 2)`, 폰에서는 높이 300).
`Y`는 `Parent.Height / 2 - Self.Height / 2`로 둔다. 높이를 하드코딩하면
(`Parent.Height / 2 - 130`) 높이를 바꿀 때마다 중앙 정렬이 깨진다.

### 4. Choice 열은 `Text()`로 감싼다

```
{보유부서: X.자산.자산보유부서}         // ✗ Choice 레코드가 그대로 들어가 JSON이 깨진다
{보유부서: Text(X.자산.자산보유부서)}   // ○
```

### 5. 내보낸 CSV의 열 순서는 가나다순이다

`JSON()`이 레코드 필드를 이름순으로 정렬한다. 지정한 순서가 아니다.
이 CSV를 되읽는 업로드 기능을 만든다면 **열은 위치가 아니라 헤더 이름으로 찾아야 한다**
(`../csv-upload/README.md` 함정 2).

### 6. `Visible`이 꺼져 있어 디자인 캔버스에 안 보일 때

미리보기로 플로우를 실제 실행하지 말고, `Visible`을 잠깐 `true`로 바꿔 캔버스에서 확인한 뒤
원래 수식(`gblExportDone`)으로 되돌린다. SharePoint에 테스트 CSV가 쌓이지 않는다.

## 앱과 이 키트가 다른 곳 하나

앱의 `conSaExportBtns`만 `LayoutJustifyContent = Center` / `LayoutGap = 8`이고,
복사본 세 개는 시작 정렬 / 간격 0이다. 이 키트에는 **정렬된 쪽**을 담았다.
앱 쪽 불일치는 사용자가 직접 조정하기로 한 것이라 그대로 두었다.
