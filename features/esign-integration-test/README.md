# 전자결재 앱 통합 기능 테스트 체크리스트

**이 키트는 `DemoElectronicApprovalLeave`(전자결재 **앱**) 것이다.**
2026-09-17 ~ 09-28에 바꾼 것들을 **게시본 플레이어**에서 한 번에 다시 확인한 기록(2026-10-01)이다.
다음에 이 앱을 크게 고친 뒤에도 같은 순서로 돌리면 된다.

---

## 시작 전에

1. **게시본 소스부터 받아 변경이 다 들어 있는지 본다** — `pac canvas download` → unpack → 핵심 토큰 grep
   (`yymmdd`, `잔여연차가 부족`, `parentsystemuserid`, `conAlpBackground`, `conApprovalLineRow`, `locFilterDateTo` …)
2. 플레이어에 **"이전 버전을 사용하고 있습니다"** 배너가 보이면 `새로 고침`부터 누른다(캐시)
3. 테스트 결재자는 **메일함이 있는 계정**({결재자})으로 넣는다. 기안자 계정에 메일함이 없으면
   결과 메일(완료·반려)은 확인할 수 없다 — 아래 "결과 메일" 참고
4. 새 기안의 결재라인은 **비어서 시작**한다(사용자 테이블 `관리자`가 비어 있으면 공란). 팝업에서 직접 넣는다
5. 데이터 기댓값은 화면이 아니라 Dataverse에서 먼저 뽑아 둔다(`pac env fetch`) — 화면과 대조한다

## A. 기안 목록 (`scrApproval`) — 데이터 변경 없음

| 항목 | 방법 | 기대 |
|---|---|---|
| 기간 검색 | 시작·종료 같은 날로 조회 | 그날 기안만 (Dataverse 건수와 일치) |
| 새로고침 | ↻ | 날짜 2칸·제목·번호·상태 드롭다운·정렬 표시 전부 초기화 |
| 상태 필터 | 드롭다운 `진행` | 진행 중인 건만 |
| 열 정렬 5개 | 헤더 두 번씩 | ▲/▼ 표시, 옛 `doc-###`·새 `YYMMDD-NN` 섞여도 순서 맞음 |
| 월 경계 | 기안일자 정렬 | **9월 ↔ 10월** 순서가 맞는다(텍스트 정렬 함정 확인) |
| 재진입 정렬 초기화 | 정렬 → 상세 → 뒤로 | 정렬 표시 사라짐 (미리보기는 변수 유지라 **게시본에서만** 확인 가능) |
| 상세 이동 | 제목 링크 / ↗ | 둘 다 상세 열림, 기안자·부서·결재선 배지 순번 |
| 폰 390px | iframe 축소 | 검색 칸 세로 배치, 표 가로 스크롤 |

## B. 새 기안 작성 (`scrElectronicApproval`) — 상신 직전 확인창에서 취소

| 항목 | 기대 |
|---|---|
| 기안자 | `이름 / 부서` |
| 결재라인 공란으로 `요청 제출` | "결재라인을 추가해주세요." |
| 결재라인 팝업 | 데스크톱 3단 / 폰 탭 2개, 역할 버튼 5개, 추가된 사람은 버튼 비활성 "추가됨", 배지 색으로 역할 구분, X 삭제 후 순번 재계산, 이름 검색은 전체 조직 |
| 팝업 `취소`·X | **열기 전 상태로 되돌아감** |
| 팝업 다시 열기 | 검색어·부서 선택 초기화 |
| 기안일자 | 오늘, 읽기 전용 |
| 휴가 잔여연차 | 승인완료된 본인 휴가 합계를 뺀 값 |
| 연차휴가 초과 | "잔여연차가 부족합니다. (잔여 X일 / 사용 Y일)" |
| 예비군·경조·업무상병가 초과 | 차단 없이 확인창까지 |
| 사용연차 | 평일만 (금~월 = 2) |
| 휴가일 | 시·분 없음 |
| 폰 | 결재라인 줄 표시, 버튼 2×2 |

## C. 상신·결재 — 실제 발송된다

| 항목 | 기대 |
|---|---|
| 바로 상신 | 기안번호 `YYMMDD-01`, 기안일자 = 상신 시각, route 1행 `진행중` |
| 임시저장 | 목록에 번호 빈칸·"임시저장", 버튼 5개(삭제 포함) |
| 임시저장 다시 열기 | 결재라인·휴가값 복원 |
| 임시저장 → 상신 | 다음 번호(`-02`), 기안일자가 **상신 시각**으로 갱신 |
| 승인 | 목록 "승인완료", 잔여연차 차감 |
| 반려 | 목록 "반려" |
| 결재요청 메일 | 결재자에게 도착, 고객명 표시 |
| 승인 카드 수 | 임시저장 → 상신도 **1장** (`msdyn_flow_approvals`로 셈) |
| 카드 휴가 날짜 | 앱에서 고른 날짜와 같음 |
| 카드 링크 | 해당 기안 상세가 바로 열림, 뒤로가기 → 목록 |

## D. 결재기한 D-1 리마인드

결재기한 = **실행일 + 1**인 건만 대상이다. **내일 받으려면 기한을 모레로** 잡는다.
대상 건은 리마인드를 확인하기 전까지 **승인·반려하지 않는다**(처리되면 대상에서 빠진다).

## 2026-10-01 결과

A·B·C 전부 통과. D는 10/2 09:00 확인 대기.
테스트 기안 3건(시연용으로 남김): `YYMMDD-01`(일반, 기한 10/3, D-1용·대기) / `YYMMDD-02`(연차 2일, 승인) / `YYMMDD-03`(일반, 반려).

### 테스트 중 찾아서 고친 것 (2026-10-01 게시 완료)

| # | 증상 | 고친 곳 |
|---|---|---|
| 1 | 결재라인 팝업 `취소`·X가 되돌리지 않음 | [`../esign-approval-line/`](../esign-approval-line/) ⑤ |
| 2 | 팝업 검색어·부서 선택이 다음 기안까지 남음 | 〃 |
| 3 | 폰 목록 기안일자 칸 ▲▼ 스크롤 화살표 | [`../search-date-range/`](../search-date-range/) 마지막 절 |
| 4 | 사용연차에 주말 포함 | [`../esign-leave-weekdays/`](../esign-leave-weekdays/) |

### 결정 대기였던 것 → 2026-10-01 같은 날 해결

자세한 원인·식은 [`../esign-approval-card/`](../esign-approval-card/).

| # | 증상 | 결과 |
|---|---|---|
| ① | 임시저장 → 상신이면 승인 카드 중복(이번엔 3장) | 같은 테이블을 보는 흐름이 3개였다(원본·전용·**{ADMIN_ACCOUNT} 소유 휴가 Test**). 원본·Test 트리거 필터에 `and cr5f6_draft_no eq null` → 카드 1장 |
| ② | 카드의 휴가 날짜가 하루 앞당겨짐 | 휴가 날짜 열은 UserLocal(UTC 저장), 커넥터는 시간 잘린 UTC 날짜를 준다 → 전용 흐름 카드 식만 `addDays(…, 1)`. 앱은 정상 |
| + | 카드 링크를 누르면 목록만 보임 | 앱에 `Param("docNo")` 처리 추가(`StartScreen` + 상세 `OnVisible`) → 해당 기안 상세가 바로 열림 |

추가 테스트 기안(남김): `YYMMDD-04`~`07`(휴가, 원인 추적·재검증용).

### 결과 메일 (완료·반려)

받는 사람은 **기안자**다(결재자 아님). 기안자 계정에 메일함이 없으면 발송은 성공해도 반송된다.
결과 메일을 눈으로 확인하려면 메일함 있는 계정으로 **기안을 올려야** 한다.
결재자에게도 보내려면 전용 흐름 메일 2개에 참조를 더해야 한다(미정).

## 함정

- 게시본 플레이어의 휠 스크롤은 기안 폼 안에서는 먹었다(목록 갤러리는 안 먹음)
- 첫 정렬 클릭에서 한 번 이상한 순서가 보였는데 재현되지 않았다 — 탭이 막 활성화된 직후 렌더링 지연으로 본다
- 승인 카드가 몇 장 나갔는지는 Dataverse `msdyn_flow_approval`(제목·결과·생성 시각)로 센다
