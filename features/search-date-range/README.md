# 조회 조건을 "~부터 ~까지" 기간 검색으로

날짜 하나로 **정확히 일치**하는 건만 찾던 조회 조건을 **기간 검색**으로 바꾼다.
전자결재 앱 `scrApproval`의 기안일자에 적용했지만, 구조가 같은 검색 화면이면 그대로 쓴다.

## 바꾸는 곳 — 컨트롤 1개 + 수식 4개

| # | 위치 | 파일 |
|---|---|---|
| 0 | 날짜 선택기 복제 | (Studio에서 `Ctrl+C` / `Ctrl+V`) |
| 1 | 화면 `OnVisible` | [`01-onvisible-init.txt`](01-onvisible-init.txt) |
| 2 | 조회 버튼 `OnSelect` | [`02-search-onselect.txt`](02-search-onselect.txt) |
| 3 | 새로고침 버튼 `OnSelect` | [`03-refresh-onselect.txt`](03-refresh-onselect.txt) |
| 4 | 갤러리 `Items` 필터 | [`04-gallery-items-filter.txt`](04-gallery-items-filter.txt) |

**기존 변수(`locFilterDate`)를 시작일로 그대로 쓰고 `locFilterDateTo`만 더한다.**
이름을 새로 지으면 네 곳을 전부 고쳐야 한다.

## 컨트롤 추가 — 복제가 가장 안전하다

기존 날짜 선택기를 트리에서 고르고 `Ctrl+C` → `Ctrl+V` 하면 **같은 부모 안에**
`dteApprovalDate_1`이 생긴다. 속성이 전부 복사되므로 스타일이 저절로 맞는다.
이름은 그대로 써도 된다 — 수식에서 `_1`이 종료일이라는 것이 드러난다.

> **`그룹` 버튼은 자동 레이아웃 컨테이너 안에서 동작하지 않는다.**
> 두 날짜를 묶으려고 눌러도 컨테이너가 생기지 않는다. 컨트롤을 옮기지 말고
> **부모를 가로+줄바꿈으로 바꾸는** 쪽이 안전하다(아래).

## 한 칸 안에 나란히 놓기 — 컨테이너를 만들지 않는다

세로 컨테이너(라벨 → 날짜)를 **가로 + 줄바꿈**으로 바꾸고, 라벨이 한 줄을 다 차지하게
하면 날짜 두 개가 다음 줄에 나란히 떨어진다.

| 컨트롤 | 속성 | 값 |
|---|---|---|
| 부모 컨테이너 | `LayoutDirection` | `LayoutDirection.Horizontal` |
| | `LayoutWrap` | `true` |
| | `Height` | 2줄치 (패딩 16 + 라벨 20 + 간격 4 + 입력 30 = **70 이상**) |
| 라벨 | `LayoutMinWidth` | `Parent.Width - 16` |
| | `Width` | `Parent.Width - 16` |
| 날짜 2개 | `Width` | `Parent.Width / 2 - 12` |

**라벨은 `LayoutMinWidth`와 `Width`를 둘 다 준다.** 줄바꿈은 `LayoutMinWidth`가 만들지만
표시 폭은 `Width`가 정한다. 기본값(150)이 남으면 라벨이 잘린다.

라벨 문구에 범위를 적어 두면 입력칸이 두 개인 이유가 드러난다 — `"기안일자 (시작 ~ 종료)"`.

## 함정

### 자동 괄호 — 맨 앞이 그냥 `(`면 닫는 괄호가 하나 남는다

```
(Parent.Width - 24) / 2     →  실제로 들어간 값: (Parent.Width - 24) / 2)
```

함수 이름 뒤의 `(`는 괜찮은데 **함수가 아닌 여는 괄호**는 자동으로 닫힌 `)`가 덮어써지지
않는다. **괄호 없는 동등식으로 바꾼다.**

```
Parent.Width / 2 - 12       ✓
```

### 속성 패널 `고급` 입력란은 여러 줄일 때 `shift+Home`이 한 줄만 잡는다

값이 감겨 여러 줄이면 그 줄만 바뀌어 수식이 깨진다.
**`ctrl+End` → `ctrl+shift+Home`**으로 전체를 잡는다. `Ctrl+A`는 이 입력란에서 쓰지 않는다
(입력란이 아니라 캔버스의 컨트롤이 선택된다).

긴 수식은 아예 클립보드로 통째 교체하는 편이 확실하다. 원문은 `pac`으로 받은 YAML에서 잘라 쓴다.

## 검증

게시본에서 실제로 조회해 확인한다. 날짜만 비교하므로 **경계 포함**이다.

| 조회 범위 | 결과 |
|---|---|
| 9/1 ~ 9/11 | 9/8 · 9/10 건만 표시. 7/27 · 9/14 · 9/15 제외 |
| 새로고침 | 날짜 두 칸 모두 비워지고 전체 복귀 |

한쪽만 고른 검색(시작일만 / 종료일만)도 `IsBlank` 가드로 동작한다.

## 폰에서 라벨 옆에 ▲▼가 생기던 것 (2026-10-01, 게시 완료)

폰(390px) 목록 화면의 기안일자 칸 오른쪽 위에 작은 ▲▼ 스크롤 화살표가 보였다.
**컨테이너가 아니라 라벨(`txtApprovalDate`, ModernText) 자체의 스크롤바**다.

- 칸 높이 76(데스크톱 72) − 위아래 패딩 16 − 간격 4 − 날짜 입력 30 → 라벨 몫이 약 22
- 라벨은 글자 13 + **기본 안쪽 여백 위·아래 5씩** → 넘쳐서 라벨 안에 스크롤바가 생긴다

**고침**: `txtApprovalDate` 안쪽 여백 **위 0 / 아래 0** (속성 패널 숫자칸, 상수라 바로 입력).
칸 높이는 건드리지 않았다. 미리보기 iPhone 12에서 ▲▼ 사라짐 확인.

> ModernText에 스크롤바가 보이면 **텍스트 크기 + 위아래 여백 > 실제 높이**부터 의심한다.
> 같은 증상이 엑셀 내보내기 팝업 제목(Size 18 / Height 32)에서도 있었다([`../excel-export/`](../excel-export/)).
