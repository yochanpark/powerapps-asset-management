PPT 장표 10·11, `scrDisposalRequest`. 장표 11은 2026-09-29 구현, 장표 10은 2026-09-30 구현 — 둘 다 **게시 완료**.
정확한 수식은 게시본에서 옮긴 [01-formulas.txt](01-formulas.txt), 검색 패널 YAML은 [02-search-panel.yaml](02-search-panel.yaml).

## 장표 11 — 요구와 결정

| 요구 | 결정 |
|---|---|
| 검색 패널로 부서 자산 검색·선택 | `scrAssetOut` 검색부를 `_Dr` 이름으로 복사 |
| 잔존기간 = 현재 − 구매, 년 단위, 기준 1/1 또는 4/1 | **4/1 회계연도 기준**: 경과 = FY(오늘) − FY(취득일), FY = Year − (Month < 4) |
| 잔존금액 = 취득가액 ÷ 기간 × 잔존기간 | 그대로. 잔존감가 범위 검색도 이 값으로 |
| 영구는 "영구" 표시 | 기간칸 "영구", 금액 = 취득가액, 감가상각 미종료로 분류 (내부값 잔존연수 = 99) |

## 장표 10 — "각 부서가 자기 자산을 검색해 파기 신청", 리뷰 코멘트 "절차 미구현"

절차 자체(신청 → 총무 승인 → 전자결재 → 자산 상태 반영)는 9/15에 종단 검증된 상태였다.
리뷰에서 "미구현"으로 보인 진짜 원인은 목록 조건 **`자산보유부서 = 로그인 사용자의 사업부`** 였다.
검토 계정은 루트 사업부 소속인데 루트 이름으로 된 자산이 없어서 늘 0건이었다(테스트 계정 4개가 모두 루트라 지금도 같다).

**결정(사용자 승인)**: 장표 13·14와 같은 기준 — **사업부 위치가 권한**.

| 내 사업부 위치 | 부서 드롭다운 | 목록 |
|---|---|---|
| 루트 | 전체 + 부서 + `└ 팀` | 고른 조직과 그 하위 팀 자산 (전체 = 조건 없음) |
| 부서 BU | 자기 부서 + `└ 하위 팀` | 〃 |
| 팀 BU | 자기 팀 1개 (비활성) | 자기 팀 자산 |

신청부서는 **로그인 사용자의 사업부가 아니라 자산의 보유부서**로 기록한다 — 루트·부서장이 신청해도 승인 화면에서 실제 팀별로 묶인다.
