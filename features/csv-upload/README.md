# 캔버스 앱 CSV 업로드 키트

DemoAssetManagement에서 **두 번** 만든 CSV 업로드 기능을 떼어낸 것이다.
세 번째부터는 이 폴더에서 꺼내 쓴다.

| 만든 것 | 화면 | 성격 |
|---|---|---|
| 재고실사 CSV 업로드 | `scrStockTakeDept` | **기존 레코드 갱신형** (자산코드로 찾아 보유여부 반영) |
| 자산등록 CSV 일괄등록 | `scrAsset` | **신규 레코드 생성형** (Patch + Defaults) |

둘 다 2026-09-15에 구현·종단 테스트 완료.

---

## 파일

| 파일 | 용도 |
|---|---|
| `01-button.yaml` | 대화상자를 여는 버튼. 화면 제목줄 컨테이너에 붙여넣는다 |
| `02-dialog.yaml` | 업로드 대화상자 한 벌(컨테이너·라벨·첨부 양식·버튼 행). 화면 직속에 붙여넣는다 |
| `03-onselect-신규등록형.txt` | 자산등록 구현 전문. 신규 생성이면 이걸 베낀다 |
| `04-onselect-기존갱신형.txt` | 재고실사 구현 전문. 기존 행 갱신이면 이걸 베낀다 |
| `template-자산등록.csv` | 사용자 배포용 CSV 양식 예시 (UTF-8 BOM) |

`01`/`02`의 `{{PFX}}`는 화면마다 다른 2글자 접두어다. 붙여넣기 **전에** 치환한다.

`AppTheme.*`(`AppTheme.Color.TextPrimary` 등)는 앱이 쓰는 테마 컴포넌트 참조다.
앱마다 컴포넌트 이름이 다르므로 **자기 앱의 테마 컴포넌트 이름으로 바꿔서** 붙여넣는다.
테마 컴포넌트가 없으면 `RGBA(...)` 리터럴로 바꿔도 된다.

```bash
# 예: 자산출고 화면이면 Ao
sed -e 's/{{PFX}}/Ao/g' 02-dialog.yaml > /tmp/dlg.yaml
```

## 전제 — 이것부터 확인

1. **첨부 컨트롤은 SharePoint 목록에 연결된 양식에서만 나온다.**
   Dataverse 테이블은 "메모 및 파일 첨부"를 켜도 캔버스 양식에 첨부 필드가 **안 나온다**
   (그 체크박스는 한 번 켜면 되돌릴 수 없으니 켜지 말 것).
   → 이미 만들어 둔 빈 목록 `CSV업로드`(`/sites/{SITE_NAME}`, 내부 `/Lists/CSV/`)를 그대로 쓴다.
   레코드는 저장하지 않는다. 첨부 컨트롤이 파일을 메모리에 들고 있는 것만 쓴다.

2. **파일 내용은 플로우가 읽어 준다.** Power Fx는 첨부 blob을 텍스트로 못 읽는다.
   → 기존 플로우 `자산관리-재고실사CSV업로드`를 **용도 무관하게 재사용**한다.
   하는 일은 "파일 → UTF-8 텍스트" 뿐이라 자산등록에도 그대로 썼다.
   이름에 "재고실사"가 들어가 헷갈리지만 새로 만들 필요 없다.

3. 앱에 데이터 원본 `CSV업로드`와 그 플로우가 추가돼 있어야 한다.
   플로우가 Studio의 흐름 추가 목록에 안 보이면 솔루션에 없는 것이다
   (Power Apps 솔루션 → Common Data Services Default Solution → 기존 항목 추가 → 클라우드 흐름 → **Dataverse 외부** 탭).

## 붙이는 순서

1. 트리에서 **화면**을 선택 → `02-dialog.yaml` 붙여넣기 (Ctrl+V)
2. 트리에서 **제목줄 버튼 컨테이너**를 선택 → `01-button.yaml` 붙여넣기
3. `btn{{PFX}}UploadRun`을 선택하고 **속성 드롭다운이 `OnSelect`인지 확인한 뒤** 수식 붙여넣기
4. 앱 검사기 오류 0 확인 → 저장 → 미리보기에서 실제 파일로 종단 테스트 → 게시

대화상자 크기는 첨부 링크가 잘리지 않는 최소값이다. 줄이지 말 것.
- 대화상자 높이 **540** (결과 메시지 자리 포함), 첨부 양식 높이 **180**
- 110/360으로 줄이면 `파일 첨부` 링크가 안 보인다

## 수식 뼈대

```
Set(gbl{{PFX}}UploadMsg, "가져오는 중...");
If(
    Not(EndsWith(First(att{{PFX}}UploadFile.Attachments).Name, ".csv")),
        → "CSV 파일(.csv)을 선택하세요. 엑셀(.xlsx)은 지원하지 않습니다."
    <그 외 사전 조건 분기들>,
    <본문>
)
```

본문 순서:
1. 플로우 호출 → `gbl{{PFX}}CsvText`
2. 줄 분리: `Filter(Split(Substitute(text, Char(13), ""), Char(10)), Not(IsBlank(Trim(Value))))`
3. 헤더를 **이름으로** 찾아 열 번호 확보 (위치로 가정하지 말 것 — 아래 함정 2)
4. 열을 못 찾으면 **조용히 넘어가지 말고 실패**시킨다 (UTF-8 안내 포함)
5. 행 파싱 → 검증 → 유효/무효 분리
6. `ForAll(유효컬렉션, Patch(...))`
7. 목록 새로고침 + `등록 n건 / 실패 m건` + 행별 사유

## 함정 (전부 실제로 당한 것)

### 1. `Choices()`의 `Value`는 텍스트가 아니다 — `Text()`로 감싼다

```
LookUp(colCat As X, X.Value = "전산장비")         // ✗ 항상 Blank. 오류도 안 난다
LookUp(colCat As X, Text(X.Value) = "전산장비")   // ○
```

`Concat(Choices(...), Value, "|")`로 찍어보면 값이 멀쩡히 나와서 더 헷갈린다.
**검사기 오류가 안 나므로 "0건 등록"으로만 드러난다.** 가장 오래 잡아먹은 함정.

### 2. 내보내기 CSV의 열 순서는 가나다순이다

`JSON()`이 레코드 필드를 이름순으로 정렬해 내보내기 때문.
그래서 **열은 위치가 아니라 헤더 이름으로 찾는다.**

### 3. 날짜는 정오로 보정한다

```
DateValue("2026-09-15")                          // ✗ 로컬 자정 → UTC 변환에서 하루 전으로 저장됨
DateAdd(DateValue("2026-09-15"), 12, TimeUnit.Hours)   // ○
```

실제로 2026-09-15가 **2026-09-14**로 들어갔다. 등록 직후 반드시 날짜를 확인할 것.

### 4. Choice 열에 Patch할 때

`LookUp(...)`이 돌려준 **레코드를 그대로 넣으면** 검사기가
`인수 '<논리명>'의 형식이 필요합니다` / `함수 'Patch'에 일부 잘못된 인수` 오류를 낸다.
→ `.Value`를 붙여 넣는다.

### 5. 자동 채번 열은 아예 넣지 않는다

`cr5f6_fnc_assetcode`는 Dataverse 자동 번호 열이라 Patch에서 빼면 `AST-YYYY-MM-NNNN`으로 알아서 채워진다.
판별법: 앱 어디에서도 그 열을 쓰지 않는데 모든 레코드가 값을 갖고 있으면 자동 채번이다.

### 6. Power Fx 일반

- `LookUp`의 3번째 인자는 조건이 아니라 **반환식**이다. 조건 2개는 `&&`로 합친다
- `!`는 부정이 아니라 필드 접근 연산자다. `Not()`을 쓴다
- `ForAll` 안에서 **순회 중인 데이터 원본을 Patch하지 않는다**. 컬렉션으로 옮기고 나서 Patch
- 파싱 실패로 오류가 나는 자리는 `IfError(..., Blank())`로 감싼다 (`DateValue`, `Value`)

### 7. Studio 붙여넣기 — 대상 확인은 매번

**붙여넣기는 "지금 선택된 컨트롤의 지금 선택된 속성"에 들어간다.**
이번에도 미리보기를 끄면서 선택이 화면으로 바뀐 걸 못 보고 `scrAsset.Fill`에
5천 자짜리 수식을 덮어썼다(`Ctrl+Z`로 복구, 검사기 오류 65건이 떴다).

수식 바에 붙여넣기 직전에 **속성 드롭다운을 눈으로 확인**한다.
`zoom`으로 수식 바 영역만 찍어 보는 것이 가장 빠르다.

## 자동화 메모 (브라우저로 작업할 때)

브라우저 자동화 전반은 [`docs/automation-notes.md`](../../docs/automation-notes.md)에 있다.
이 기능에서 특히 걸리는 것만 짚으면:

- **Studio UI(트리·수식 바)** = OS 레벨 실제 클릭(`mouse_event`) /
  **앱 캔버스(미리보기 중)** = 확장 도구(CDP) 클릭. 서로 바꿔 쓰면 조용히 실패한다
- **파일 선택 창**은 한글 경로 붙여넣기가 안 된다 — **영문 이름 사본**을 만들어 쓰면 편하다
- 미리보기를 끈 직후 트리 클릭은 **한 번에 안 먹는다.** 1초 기다렸다 단일 클릭하고,
  `zoom`으로 속성 드롭다운을 확인한 뒤 다음 단계로 간다

## 테스트 자료 만드는 법

UTF-8 **BOM 포함**으로 써야 한다(엑셀이 한글을 제대로 연다).

```bash
printf '\xef\xbb\xbf' > test.csv
cat >> test.csv <<'CSV'
자산명,분류,취득일,취득가액,감가상각기간,자산보유부서
[테스트] 노트북,전산장비,2026-09-15,1800000,5년,연구소
CSV
```

정상 파일과 **오류 섞인 파일**을 둘 다 만들어 테스트한다.
오류 파일에는 빈 필수값 / 없는 Choice 값 / 날짜 아닌 문자열을 한 줄씩 넣는다.

**테스트 레코드는 실제 테이블에 남는다.** 자산명에 `[테스트]` 접두어를 붙여 나중에 지울 수 있게 한다.
앱에 삭제 기능이 없으면 Power Apps 테이블 편집기에서 지워야 한다.
