총무(장표 14)·통계(장표 13)의 조직 필터가 "부서를 눌러도 자산이 정확히 안 나온다"는 사용자 제보에서 시작했다.

## 원인

두 화면의 조직 필터는 자산의 **`자산보유부서` 텍스트가 사업부(Business Unit) 이름과 같은지**로 거른다.

```
(CountRows(colSaOrgScope) = 0 || R.자산.자산보유부서 in colSaOrgScope.이름)     // 총무
gblRpSelKind = "전체" || 자산보유부서 in colRpScope.이름                          // 통계
```

초기에 자유 입력으로 넣은 부서명이 남아 있으면:

| 증상 | 이유 |
|---|---|
| 부서를 체크하면 일부 팀 자산만 나온다 | 사업부 이름과 맞는 자산만 통과 |
| 어떤 부서·팀은 늘 0건 | 그 이름으로 저장된 자산이 없음 |
| 체크를 다 풀면 전부 나온다 | `CountRows(scope) = 0` 분기가 전부 통과 |
| `공용`과 `[공용]`이 따로 집계 | 등록 화면은 `[공용]`으로 저장, 옛 데이터는 `공용` |

실측(9/30): 자산 16건 중 **사업부 이름과 맞는 것은 한 팀의 4건뿐**, 나머지 12건은 자유 입력 11종 + 빈값.

## 함정

- 총무 KPI `제출 부서 N / M`의 **M은 실사 헤더 수가 아니라 자산 보유부서 종류 수**다
- **Studio 미리보기는 데이터 원본을 캐시한다.** API로 바꾼 값은 홈 → 타일로 다시 들어가야 보인다
- 앱이 파기 신청을 넣을 때는 자산 상태도 **파기신청(6)**으로 바꾼다. 테스트 신청도 맞춰야 신청 화면에 같은 자산이 다시 뜨지 않는다
- 파기 승인 화면 `OnVisible`은 전자결재 결과를 반영하는 Patch를 돈다 — 미리보기로 열기만 해도 실행된다
- 자동 모드 분류기는 Dataverse 쓰기를 `Modify Shared Resources`로 막는다(PATCH·POST·DELETE 모두, 일정하지 않음). 사용자가 권한을 연 뒤 진행
- 테스트 계정의 **사업부 변경은 보안 설정 변경**이라 사용자가 직접 한다. 바꾸면 보안 역할이 모두 빠지니 다시 넣어야 한다
