# 기안일자를 상신 시각으로 자동 기록

사용자가 날짜를 직접 고르던 `기안일자`를 **기안을 올린 시각**으로 자동 확정한다.
폼에서는 읽기 전용으로 보여 주고, 값은 상신하는 순간 `Now()`로 덮어쓴다.

## 왜 필요했나

폼에 날짜 선택기가 있고 **시·분 드롭다운은 `Visible: false`로 숨어 있었다.**
카드의 `Update`가 숨은 드롭다운에서 시·분을 읽는데 기본값이 `00`이라
**저장된 값이 전부 `0시00분`**이었다. 언제 올린 기안인지 알 수 없다.

## 바꾸는 곳 — 수식 7개

| # | 위치 | 파일 |
|---|---|---|
| 1 | 상신 확인 팝업 `확인` 버튼 `OnSelect` | [`01-submit-onselect.txt`](01-submit-onselect.txt) |
| 2~7 | 기안일자 카드의 날짜·시·분 컨트롤 | [`02-readonly-date-card.txt`](02-readonly-date-card.txt) |

## 동작

| 시점 | 기안일자 |
|---|---|
| 새 기안 폼 | 오늘 날짜가 읽기 전용으로 채워져 보임 (클릭해도 달력이 안 열린다) |
| 임시저장 | 저장한 시점의 날짜 + 시:분 |
| **상신(요청 제출)** | **`Now()`로 확정** |

`Patch`의 **명시 레코드가 `Form.Updates`보다 나중**이라 폼이 만든 값을 덮어쓴다.
순서를 바꾸면 폼 값이 이긴다.

## 함정

### `DefaultDate`를 안 고치면 상신이 막힌다

`기안일자`는 `Required: true`다. 새 기안에서는 원본 레코드가 없어 `DefaultDate`가 비고,
그러면 `Form.Valid`가 `false`라 **요청 제출 버튼이 검증에서 걸린다.**
읽기 전용으로 만들 때는 **값을 채워 두는 것이 한 세트**다.

```
DefaultDate = If(IsBlank(varApprovalDetail.기안일자), Now(), varApprovalDetail.기안일자)
```

### 숨은 컨트롤도 같이 고친다

시·분 드롭다운은 화면에 안 보이지만 **카드의 `Update`가 값을 읽는다.**
`Default`를 그대로 두면 임시저장 값이 계속 `0시00분`으로 들어간다.

### 기간 검색과 충돌하지 않는다

조회 필터가 `DateValue(Text(기안일자, "yyyy-mm-dd"))`로 **날짜만 비교**하므로
값에 시간이 들어가도 [기간 검색](../search-date-range/README.md)은 그대로 동작한다.

## 검증에서 멈춘 곳

**실제로 기안을 상신해 보지는 않았다.** 상신하면 `approval_route` 행이 생기고
**결재 알림이 실제 결재자에게 발송된다.** 테스트 데이터를 만들고 남에게 알림을 보내는 일이라
수식과 게시본 대조까지만 하고 멈췄다.

폼에서 확인할 수 있는 것까지는 봤다 — 새 기안에 오늘 날짜가 읽기 전용으로 채워지고,
클릭해도 달력이 열리지 않는다. **목록의 기안일자가 `0시00분`이 아닌 실제 시각으로 찍히는지는
다음 실제 기안에서 확인해야 한다.**
