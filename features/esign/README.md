# 캔버스 앱 ↔ 전자결재 연동 키트

업무 화면에서 **전자결재를 상신하고, Teams 승인 결과를 업무 레코드에 되돌리는** 한 바퀴.
DemoAssetManagement의 자산파기(`scrDisposalApprove`)에 붙인 것을 떼어냈다.

2026-09-15에 **실제 데이터로 종단 검증 완료** — 상신 → 플로우 → Teams 승인 → 앱 반영까지.

| 단계 | 주체 |
|---|---|
| 상신 (기안·결재선 생성, 문서번호 기록, 플로우 호출) | 앱 |
| Teams 승인 카드 발송, 결재 결과를 `approval_route`에 기록 | **Power Automate 플로우** |
| 결과를 업무 레코드·자산 상태에 반영 | 앱 (화면 진입 시) |

```bash
sed -e 's/{{PFX}}/Da/g' 01-dialog.yaml > /tmp/dlg.yaml
```

## 전제 — 이것부터 확인

1. **데이터 원본 `approval_master`, `approval_route`를 앱에 추가**한다.
   `사용자`(systemuser)도 필요하다.

2. **승인 플로우를 먼저 만들고 앱에 붙인다.**
   플로우 없이 상신하면 데이터만 쌓이고 **Teams 승인 요청이 나가지 않는다.**
   Power Automate 창 → 흐름 추가로 앱에 붙인 뒤에야 `.Run()`이 쓸 수 있다.

3. **기안유형 Choice에 해당 업무 값이 있는지** 본다. 없으면 전역 Choice에 추가해야 한다.

4. **업무 테이블에 문서번호를 담을 텍스트 열**이 필요하다.
   자산파기는 `tsk_approvaldocno`가 원래 있어서 스키마 변경이 없었다.

## 붙이는 순서

1. 트리에서 **화면** 선택 → `01-dialog.yaml` 붙여넣기
2. 상신 버튼을 만들고 `Set(gbl{{PFX}}EsignOpen, true)` 를 `OnSelect`에 넣는다
3. `btn{{PFX}}EsignSubmit` 선택 → **속성 드롭다운이 `OnSelect`인지 눈으로 확인** →
   `02-submit-onselect.txt`의 한 줄짜리 수식 붙여넣기
4. 화면 `OnVisible` **맨 앞**에 `03-reflect-onvisible.txt` 붙여넣기
5. 앱 검사기 오류 0 확인 → 저장 → 게시
6. 실제로 한 바퀴 돌려 검증 (아래)

### 종단 검증 한 바퀴

상신 → 전자결재 앱 기안 목록에 뜨는지 → Teams 승인 카드 도착 → 승인 →
`approval_route.결재상태`가 `승인`으로 바뀌었는지 → **앱 화면 재진입** → 업무 레코드와 자산 상태 반영 확인.

이 과정에서 **자산 1건이 실제로 소진된다.** 테스트용 레코드를 준비해 두고 시작한다.

## 모바일 (폰) 대응

앱 설정이 `ScaleToFit: false` / `MaintainAspectRatio: false`면 **폰에서 자동 축소로 구제되지 않는다.**
설계 폭이 1366이어도 폰에서는 진짜 390px로 그려진다. 고정 폭 팝업은 그대로 잘려 나간다.

`01-dialog.yaml`은 반응형으로 고쳐 뒀다. 직접 붙일 때 지킬 것은 세 가지다.

| 속성 | 수식 | 이유 |
|---|---|---|
| `Width` | `Min(480, Parent.Width - 32)` | 폰에서 화면보다 넓어지지 않게 |
| `X` | `Max(16, (Parent.Width - 480) / 2)` | 넓을 땐 가운데, 좁을 땐 좌우 16 여백 |
| `Height` | `If(App.Width < 768, 300, 228)` | 좁아지면 라벨이 줄바꿈해 세로가 더 필요하다 |

콤보박스에 `Width: =Parent.Width - 48`을 **명시**한다. 안 주면 기본 폭이 좁아진 팝업을 넘친다.

### `X`에 `Self.Width`를 쓰면 순환 참조다

가운데 정렬이라 `(Parent.Width - Self.Width) / 2`가 자연스러운데 **오류가 난다.**
`Y`의 `Parent.Height / 2 - Self.Height / 2`는 멀쩡히 동작해서 더 헷갈린다.
폭 계산을 `X` 안에 다시 쓰거나, 위 표처럼 `Max()`로 바닥을 깔아 `Self`를 피한다.

### 브레이크포인트는 768로 맞춘다

헤더 컴포넌트가 이미 `App.Width >= 768`로 데스크톱/모바일을 가른다. 다른 값을 쓰면
헤더는 모바일인데 본문은 데스크톱인 구간이 생긴다.

## 함정 (전부 실제로 당한 것)

### 1. 승인 기능은 앱에 없다 — 플로우에 있다

캔버스 앱을 아무리 grep해도 결재 처리 코드가 안 나온다.
**앱에 없다고 기능이 없는 게 아니다.** `04-tables-and-flow.md`를 볼 것.

### 2. `현재결재상태` 텍스트 열을 믿지 말 것

플로우가 이 열을 갱신하지 않아 상신 때 넣은 `"결재대기"`가 그대로 남는다.
**기안 상태는 `approval_route` 행들로 계산한다.** 판정식은 `04-tables-and-flow.md`.

### 3. 문서번호 기록은 기존 엔진 실행 **앞**에

```
ForAll(... Patch(fnc_assetdisposal, G.신청, {전자결재문서번호: ...}));
Select(btnDaEsignRun);     ← 이 안에서 Clear(colDaSelected)가 돈다
```

뒤에 두면 선택이 날아가 대상을 못 찾는다.

### 4. 문서번호 없이 상태만 바꾸면 레코드가 끼인다

반영 블록은 `전자결재상신 AND 문서번호 있음`, 목록 적재는 `신청`을 본다.
→ **`전자결재상신`인데 문서번호가 비면 어디에도 안 잡힌다.**
화면은 0건으로 보이고 데이터는 멀쩡히 남는다. 되살리려면 상태를 `신청`으로 되돌린다.

### 5. `.Run()` 인자는 논리명이 아니라 기본 키 열의 **표시 이름**

```
tsk_approval_masterid → approval_master
systemuserid          → 사용자
```

`msapp`의 `References\DataSources.json` → `NativeCDSDataSourceInfoNameMapping`에서 확인한다.
Studio 인텔리센스보다 빠르다.

### 6. 이름의 공백

- 흐름 식별자는 앱에 붙을 때 **공백이 빠진다**: `자산관리_자산파기 승인` → `'자산관리_자산파기승인'`
- 데이터 원본 `'사용자 '`는 **끝에 공백이 있다**. 열 이름에는 없다

### 7. 기존 버튼은 지우지 말고 숨겨서 엔진으로 쓴다

원래 있던 버튼이 목록 갱신 로직을 길게 들고 있었다.
이름만 바꾸고 `Visible = false`로 숨긴 뒤 `Select()`로 호출했다.
**긴 로직을 한 줄도 건드리지 않고** 재사용한 것이다.

### 8. 반영 대상은 컬렉션으로 옮긴 뒤 Patch

`ForAll` 안에서 순회 중인 데이터 원본을 Patch하면 안 된다.
`ClearCollect` 먼저, 그다음 컬렉션을 돌면서 원본을 고친다.
